# Repository Guidelines

## Project scope

Nagi is a local-first work execution system for Linear, Codex CLI, and Cursor
Agent CLI. The repository is currently in its foundation phase; implementation
changes belong in focused pull requests.

## Agent runtime boundary

- The authoritative architecture is Linear ↔ standalone Nagi controller,
  SQLite, and Temporal ↔ Herdr CLI or Unix socket API ↔ Herdr workspace, pane,
  and session runtime ↔ Codex CLI or Cursor Agent CLI. See
  [ADR-0003](docs/adr/0003-herdr-agent-runtime-boundary.md).
- Nagi owns Linear state, claims, retry, reconciliation, acceptance and result
  validation, GitHub PR/CI state, and durable attempt state. Herdr owns
  workspaces, panes, PTYs, vendor launch, session restore, and operator
  interaction. Nagi must not reimplement vendor TUIs or protocols.
- The backend boundary is `workspace_create`, `agent_start`, `prompt`,
  `observe`, `interrupt`, `resume`, `collect_report`, and `stop`. Implement
  `herdr+codex` first, then `herdr+cursor-agent`; Cursor means Cursor Agent
  CLI, never the desktop application.
- Treat Herdr lifecycle as observation only. Use the CLI for ordinary
  orchestration and the socket API for snapshots, subscriptions, and long-lived
  tracking. `idle`, `done`, and `blocked` never directly imply Linear `Done`.
- Hooks may report session start/restore/exit, supported semantic lifecycle,
  stable session references, and validated reports. They must not own
  credentials, scheduling, claims, retries, acceptance, completion decisions,
  or durable controller state. Validate source IDs, monotonic sequences, TTLs,
  attempt IDs, duplicate/out-of-order events, and unknown states. Installation
  must be explicit and reversible; never silently rewrite agent configuration.
- Herdr and vendor CLIs are external operator-installed runtime dependencies,
  not bundled helpers. Keep the production artifact as one standalone Nagi
  executable and do not pin a Herdr version before its contract PR.
- Codex App Server is an optional future high-fidelity backend, not a mandatory
  Phase 0 gate. Preserve the unmerged P0-12 work, but do not merge or resume
  it as Phase 0 or run its old provider contract.

## Contribution rules

- Write commits, pull request titles and bodies, documentation, comments, and workflow messages in English only.
- Use Conventional Commits for pull request titles: `feat`, `fix`, `docs`, `refactor`, `test`, `ci`, `build`, `chore`, `perf`, or `revert`.
- Never push directly to `main`. Open a pull request and squash-merge it after the required checks and review pass.
- Sign commits. Do not amend or rewrite commits that have already been merged.
- Keep changes focused and do not add implementation code to setup-only changes.
- Use the Apache License 2.0 for this repository.

## Worktrees and pull requests

- Give every pull request one dedicated worktree and one focused concern. Do not share a worktree between concurrent pull requests, and do not mix unrelated changes into the worktree.
- Before editing, check the worktree branch and status. Preserve unrelated user changes and keep the pull request branch based on an explicit base commit.
- Require both a current-SHA adversarial review and a current-SHA ponytail review against the same SHA, and record that exact reviewed and checked commit SHA in the evidence. A branch change invalidates both reviews and checks; make a new signed commit and never amend or rewrite the reviewed or shared commit.
- A release pull request must state its base and release SHAs and must not duplicate an active implementation pull request. If the release pull request overlaps an active change, pause it, reconcile it with the current base, and rerun checks and both reviews before merging.
- After a pull request is merged or closed, clean up only its exact worktree and temporary artifacts after confirming the path, branch, status, and preserved evidence. Never use broad globs or a repository/home root for cleanup, and never remove credentials, shared state, or review evidence as part of cleanup.

## Local tooling

Install the pinned tools with:

```bash
mise install --locked
```

Run these checks before opening a pull request:

```bash
mise run lint
mise run test
mise run build
```

The Rust tasks skip project commands until `Cargo.toml` exists. This keeps the foundation usable before implementation starts.

## Contract harness know-how

- Keep the Phase 0 tool revisions in `contracts/versions.toml` and platform artifact URLs/checksums in `mise.lock`; use the explicit `aqua:temporalio/cli` tool name because the shorter `temporal` alias refers to a different upstream.
- When the Temporal Rust SDK is introduced, use the exact crates.io `temporalio-sdk = "=0.7.0"` dependency and commit the resulting `Cargo.lock`; do not add an unused Git dependency.
- The Herdr CLI/socket contract is an opt-in macOS witness at `mise run contract:herdr`, pinned to Herdr `0.8.2` (peeled revision `9eb521456ac0d19d3ab3d9d7cea3cca10baa8a4c`), API protocol `20`, and schema `1`. It uses an isolated `HOME` and named synthetic session, the CLI for orchestration, and the raw Unix socket for snapshots and subscriptions; after a graceful restart it takes one fresh snapshot. Agent interruption/resume, crash recovery, reconnect event reconciliation, and lifecycle handling remain in the later Agent observation and recovery gate; the contract never touches the normal user configuration or session.
- The Phase 0 Herdr runner binds its CLI and socket to the same validated named session and derives the socket location from the isolated `HOME`; it accepts only bounded, schema-shaped identifiers and launch witnesses, captures process output privately, and exposes lifecycle as observation only. Executable and runtime path ancestors are checked for symlinks, root/current-user ownership, and unsafe write/set-id bits, with only a root-owned sticky temporary-directory ancestor tolerated. Exact version checks are repeated before CLI mutations, but same-UID replacement between validation and execution and self-attested version output remain residual risks; immutable artifact provenance and a verified private executable copy are later signed runtime-manifest work. Prompts necessarily appear in a Herdr CLI argv element during the short-lived call and are never logged or persisted.
- The `herdr+cursor-agent` adapter uses Herdr's `--kind cursor` launch witness and canonical `agent` argv while keeping PTY and vendor launch inside Herdr; Cursor means the Cursor Agent CLI, never the desktop app. Cursor authentication remains operator-managed and out-of-band, with no direct Cursor process/protocol/TUI, PAT/API-key/user fallback, or automatic config/hook installation.
- The hook recovery witness is the transport-free `nagi::herdr_recovery` state machine: a fresh bounded snapshot establishes the exact source/attempt binding and generation, then only fresh contiguous schema-1 observations are accepted. Reconnects, gaps, generation changes, unknown values, stale/future timestamps, duplicate conflicts, and invalid ordering fail closed; exact duplicates are idempotent. Session lifecycle and report references remain observations, and no event exposes a Linear-completion decision.
- The normalized agent report is backend-neutral and strictly parsed by `nagi::agent_report` against schema version `1`: it contains only the attempt/backend/session references, closed outcome, validation status, optional sanitized commit/PR references, and bounded summary. Trusted adapters sanitize before construction/submission; parser shape, bound, control, protocol, known-path, and known-credential checks are defense in depth and cannot prove arbitrary redaction. Accepted report content is local-sensitive and never copied into public evidence; raw terminal output, prompts, provider payloads, tokens, and private machine paths must never be persisted there, and `done` never authorizes Linear completion.
- The Phase 1 durable attempt store is a standalone SQLite boundary using pinned bundled SQLite. It accepts only schema `1`, an explicit owner-only regular database path, exact canonical issue UUIDs, closed Herdr backend values, observation-only lifecycle state, bounded opaque references, validated reports, and epoch-millisecond timestamps. Starting an attempt atomically binds required workspace and agent references; exact retries are idempotent and rebinding is rejected. It enables WAL, foreign keys, a bounded busy timeout, and synchronous `FULL`; unknown schema/path shapes fail closed, and prompts, terminal/provider data, credentials, and machine paths never enter row data. Database identity is checked across open, existing WAL/SHM sidecars are checked, and the immediate state directory must be owner-only `0700`. SQLite WAL locking conflicts with a held database `flock` on macOS, so cooperating Nagi processes use a nonblocking flock on that validated state-directory descriptor; a same-UID actor can still replace a parent or final path after checks, so this is not a race-free path proof.
- The Phase 1 single-issue work commands accept only an explicit owner-only JSON configuration and one exact Linear issue UUID. `work start` reads the issue in memory, durably binds Herdr workspace/agent references, and submits one bounded prompt; `status`, `interrupt`, and `collect` reattach through those opaque runtime-bound references. Work commands serialize through the validated state-directory descriptor held by `AttemptStore`; no adjacent lock file is created. `work list` exposes keyset-paginated bounded attempt metadata, and `work resolve` is the explicit operator decision for an ambiguous pending effect; absent snapshots never trigger an automatic create/start retry. Public output contains only attempt/status or report-presence metadata; Herdr lifecycle remains observation-only, and work commands never mutate Linear or install hooks/configuration.
- Recovery-only `work list` and `work resolve` configuration needs only the owner-only `attempt_db` locator; known full-runtime fields are ignored and unknown names fail closed. Full effect commands retain strict validation of every runtime binding.
- P0-08 Temporal message handling is an opt-in macOS-only contract at `mise run contract:temporal-messages` (`NAGI_CONTRACT_TEMPORAL_MESSAGES=1`). Its thin public `scripts/contracts/temporal-messages.sh` entrypoint invokes the shared closed-mode `scripts/contracts/temporal-sdk-contract.sh` in `message` mode, which fixes feature `temporal-message-contract`, test `temporal_message_contract`, target `target/nagi-temporal-message-contract`, binary digest binding `NAGI_CONTRACT_TEMPORAL_MESSAGE_BINARY_SHA256`, and fixture `synthetic.temporal-message.v1`. The shared wrapper requires a clean checked revision, validates the installed `rust@1.98.0` and `protoc@36.1` distribution trees as canonical current-user-owned trees containing only directories and single-link regular files with no group/other write bits, then APFS-clone-copies both complete distributions into an exact private store. These current-user-owned Rust and protoc distributions are trusted local inputs: this contract verifies exact versions, clone integrity, and unchanged private executable digests across the build, but does not prove absence of same-UID replacement races or immutable official-archive provenance; it does not claim that mise provides a stronger provenance guarantee. The bounded build uses only the private Rust/protoc `PATH`, mode-0700 `HOME` and `CARGO_HOME`, and clone-copied Cargo registry cache/index trees for an offline checksum-locked build; developer Cargo configuration, credentials, unpacked sources, and mise read/write state are not used. It probes exact `rustc`, `cargo`, and `protoc` versions, binds each source executable SHA-256 before cloning, requires matching private copies, and verifies the private hashes remain unchanged across the build. Cargo build output is discarded inside the unlimited-file-limit build child. Probe output is capped and matched exactly. The outer supervisor for `temporal.sh` intentionally has no child file-size limit: `temporal.sh` emits only fixed generic diagnostics/evidence, while the provider sidecar's own output is captured and checked privately by `temporal.sh`; the wrapper checks its resulting private files but does not claim an OS-level hard limit for arbitrary raw sidecar output. The dedicated target is removed only after bounded cleanup. It runs the prebuilt binary through the P0-07 sidecar harness. `temporalio-client` 0.7.0 generates Signal-With-Start transport request IDs internally and does not expose one through `WorkflowStartOptions`, so resend safety is proved with a stable application logical message ID plus the full canonical signal payload and an observed duplicate delivery; a matching logical ID with any changed payload field is rejected. Every Signal-With-Start request explicitly combines `UseExisting` for a running execution with `RejectDuplicate` for a closed execution. After completion, a same-ID retry must return `Err(WorkflowStartError::Rpc(status))` with `status.code() == tonic::Code::AlreadyExists`; temporalio-client 0.7.0 maps `AlreadyExists` to `AlreadyStarted` only on the ordinary `StartWorkflowExecution` path, while the Signal-With-Start path preserves the gRPC status. The retry must not create a new run or mutate the closed execution. The SDK/protoc tools are build-only; no Temporal SDK code enters the standalone production binary or runtime, and no app bundle or signing profile is involved.
- The Aqua Codex `0.151.0` pin is shared by the managed authentication boundary and future contract tooling. P0-11 managed authentication remains dormant until the `herdr+codex` contract proves it is needed; changing or removing it otherwise requires a separate corrective ADR/PR. It is not an App Server Phase 0 gate.

## Linear OAuth boundary

- The P0-03 OAuth implementation is the library operation in `nagi::linear::oauth`; it returns a validated in-memory token bundle and is not a CLI persistence or refresh flow.
- Keep the Linear OAuth endpoints, `actor=app`, `scope=read`, PKCE S256, and loopback callback shape fixed. Only the client identifier and numeric callback port may come from local configuration; never add a client secret, PAT fallback, or provider-data call to this boundary.
- Browser, clock, callback listener, entropy, and token transport effects remain injectable so tests stay hermetic. Keychain persistence and later token or actor operations belong to their separately scoped implementation changes.
- P0-04 credential state is one strict bounded envelope in the user's default file-based macOS Keychain (normally the login Keychain), selected through `SecItem` with fixed generic-password service/account selectors. The standalone executable supplies no data-protection selector, synchronizable attribute, access group, bundle wrapper, provisioning profile, or restricted entitlement. The legacy file-Keychain ACL/shim model has no explicit app access-group isolation; restart persistence assumes the same default Keychain remains selected, and stronger identity/ACL proof is a later gate. Persisted lifecycle timestamps use Unix epoch milliseconds. Refresh/revoke intent transitions are persisted and verified while holding the process/advisory lock; uncertain outcomes remain blocked and are never silently retried. Tokens are never written in plaintext to logs, SQLite, prompts, worktrees, or evidence, and there is no PAT, user-actor, or memory-only fallback or silent store migration. The default-off `macos-keychain-contract` feature runs the raw Cargo-built `nagi` executable from fresh processes with a fixed synthetic locator and nonproduction account; its contract working directory must remain empty, child output is capped and redacted, and timed-out children are killed and reaped. The roundtrip succeeds without a provisioning profile supplied by the harness and is the runtime packaging check for the plain executable; it does not prove ACL or signing-identity behavior. The Keychain is selector-based rather than transactional CAS, and Security.framework copies cannot be promised zeroized. Linux returns a typed unsupported result without touching local state.
- P0-05 Linear read checks use only exact operator-supplied canonical lowercase UUID bindings for the organization, team, and setup issue; shorthand IDs are rejected rather than normalized. The GraphQL `viewer` must report `app=true` and `isMe=true`, remain stable across pages, and be durably bound to the exact OAuth client ID in the credential envelope. Private app registration and administrator consent remain out-of-band. Never enumerate provider collections or compare an actor ID with a workspace ID.
- The Phase 1 Linear issue-input facade reads exactly one bound issue through the fixed GraphQL endpoint, returns only bounded in-memory fields, and keeps the app viewer binding under the credential lock; issue text is never serialized or persisted, and comments, attachments, users, PATs, custom endpoints, and fallback actors remain outside this boundary.
- P0-05 live execution resolves its own checkout, builds the ordinary raw `target/nagi-contract/debug/nagi` executable from the exact clean checked revision through the locked mise Rust toolchain, verifies its embedded revision/native file type/path and a stable artifact digest, and supervises both the bounded build and one bounded read child in contained process groups. The runner passes only validated non-secret bindings and the selected `HOME`, invokes the explicit read command through the existing P0-04 access-token lease, and never accepts token-shaped environment values, user-actor fallback, domain-data writes, app-like bundles, signing/profile requirements, or inherited environment. Public evidence is printed only after exact closed-record validation.
- P0-06 polling contract tests use only the test-only loopback synthetic GraphQL server; production endpoints remain non-configurable here. Issue head and scan documents must carry the exact team binding, `includeArchived: true`, and bounded `first` values. Upper bounds come from the provider response, scans use inclusive `updatedAt` bounds with overlap, and the watermark changes only after every root and nested page succeeds.
- P0-07 Temporal persistence is an opt-in macOS-only local contract at `mise run contract:temporal` (`NAGI_CONTRACT_TEMPORAL=1`). The public mise entrypoint activates the exact `[tools]` `aqua:temporalio/cli = "1.8.2"` selection from `mise.toml`/`mise.lock`; the script resolves only a `temporal` PATH candidate with the non-executing Bash `type -P` builtin, uses that candidate solely as a copy source, and executes only the owner-only `0500`, single-link private copy after cross-checking its architecture-specific executable digest and official release archive URL/checksum against `contracts/temporal-cli-provenance.json` and `mise.lock`. A shadowed or substituted candidate fails closed before execution. The script verifies the private copy's native file type and version, starts `server start-dev` on randomized IPv4 loopback ports with a file-backed SQLite database and config loading disabled, and passes a fixed client identity. The witness starts a fixed synthetic namespace and Workflow, records its opaque identity/status and exact history, kills and reaps the process group, then restarts a fresh loopback port against the same database without the namespace declaration and compares the recovered identity/status and history. Listener and SQLite companion paths are checked without opening the database, child output is bounded and discarded, and the temporary store is removed only after bounded cleanup. SQLite PRAGMA and crash-recovery policy belong to P0-15. This contract does not run in default CI, use the Temporal Rust SDK, or prove production Worker behavior.
- P0-09 Temporal Activity recovery is an opt-in macOS-only local contract at `mise run contract:temporal-activities` (`NAGI_CONTRACT_TEMPORAL_ACTIVITIES=1`). Its thin public `scripts/contracts/temporal-activities.sh` entrypoint selects the fixed `activity` mode of the shared closed-mode `scripts/contracts/temporal-sdk-contract.sh` wrapper. That mode reuses the P0-08 owner-only Rust `1.98.0`/protoc `36.1` APFS-clone and offline Cargo registry build while fixing feature `temporal-activity-contract`, test `temporal_activity_contract`, target `target/nagi-temporal-activity-contract`, binary digest binding `NAGI_CONTRACT_TEMPORAL_ACTIVITY_BINARY_SHA256`, fixture `synthetic.temporal-activity.v1`, and the Activity-only extended outer cleanup grace; the SDK remains test-only and the production artifact remains one standalone executable. A synthetic long-running Activity heartbeats a typed checkpoint; a replacement Worker must resume from `ActivityContext::heartbeat_details()` and never a filesystem checkpoint. The harness waits beyond heartbeat throttling, force-kills the Worker with SIGKILL, requires the signal-derived wait status plus explicit wait/reap and PID/PGID disappearance, then repeats the gate after force-killing and restarting the Temporal sidecar against the same file-backed SQLite database. Later SDK clients bind the exact initial run ID (including `first_execution_run_id`) rather than targeting the latest execution. SDK history fetch and private CLI snapshots require monotonic contiguous event IDs, the original/current run IDs, no Continue-As-New/replacement, and a canonical full-event pre-restart event prefix in the final history. Cancellation is acknowledged by a fixed `cancelled_with_details` witness decoded from `ActivityExecutionError::Cancelled`, followed by independent cleanup; process exit is not treated as cancellation evidence. All children, listeners, output, and temporary state are private, bounded, and cleaned only after reaping; public evidence is fixed and redacted. Installed tool trees remain trusted current-user-owned inputs and the same-UID replacement limitation is explicit.
- P0-10 Temporal replay compatibility is an opt-in macOS-only local contract at `mise run contract:temporal-replay` (`NAGI_CONTRACT_TEMPORAL_REPLAY=1`). Its thin `scripts/contracts/temporal-replay.sh` entrypoint selects the closed wrapper's literal `replay` mode, which fixes feature `temporal-replay-contract`, test `temporal_replay_contract`, target `target/nagi-temporal-replay-contract`, binary digest binding `NAGI_CONTRACT_TEMPORAL_REPLAY_BINARY_SHA256`, and fixture `synthetic.temporal-replay.v1`. The pinned Temporal CLI `1.8.2` sidecar is the history producer: its architecture-specific archive URL, archive SHA-256, executable SHA-256, native file type, and version are checked against `contracts/temporal-cli-provenance.json` and `mise.lock`, and the producer runs only from the clean checked revision. The live witness creates genuine legacy and current two-run Continue-As-New chains, fetches each exact run, and requires the event linkage and `first_execution_run_id`/`original_execution_run_id`/`continued_execution_run_id` fields to match; it never follows a latest-run alias. Raw sidecar captures and producer details stay private and bounded. Public Temporal `History` files canonicalize worker identity, Build ID, and worker/deployment metadata to fixed synthetic values and contain no source-derived Build ID; the separate provenance manifest records the reviewed producer and artifact digests. These sanitized fixtures are intentionally committed/public, and the default `mise run test` replays them server-free with `WorkflowReplayer`. Checked-corpus reads reject a symlink at the final leaf with Unix `O_NOFOLLOW`, but parent-component checks are preflight only and a same-UID actor may replace a parent after that check; this residual path-component race is documented and not claimed closed. The legacy no-marker history remains compatible with the legacy definition; current marker history is compatible with the current definition, while replay under the legacy definition or an unknown/mismatched patch marker fails with Temporal nondeterminism. The manifest records `"deploymentVersioning": "not_exercised"` and no routing claim. Each worker carries a deterministic Build ID through `WorkerDeploymentOptions::from_build_id` with `use_worker_versioning == false`, an explicit UNVERSIONED poller witness; Worker Deployment Versioning routing, registration, pinning, ramping, and selection are not exercised. The local replay wrapper's signature gate checks only for a `gpgsig` header in the checked commit object; it does not establish signer identity or trust. GitHub Verified delivery and the repository's required merge checks provide that trusted delivery gate. The wrapper binds the checked test-binary digest and accepts the sidecar only when the reviewed manifest and lockfile digests agree. Public command output is one fixed redacted evidence record and never contains raw histories, manifest contents, UUIDs, or paths. The SDK remains test-only and the production artifact remains one standalone executable. The checked producer is required to be a signed clean producer revision; an unsigned or dirty source revision is rejected before export.

- P0-10 output handling keeps SDK test stdout/stderr path- and credential-redacted, while private Temporal sidecar stdout/stderr remain bounded and credential-redacted but may retain the expected run-private SQLite path emitted by the CLI startup banner.
- P0-11 managed Codex authentication is a dormant, conditional boundary and exposes only `nagi auth codex login|status|logout` on macOS if the selected `herdr+codex` path proves it necessary. It invokes the exact pinned foreground commands with a cleared environment, fixed ChatGPT/keyring configuration, validated deployment `HOME`, and dedicated `CODEX_HOME=~/Library/Application Support/nagi/codex-home`; login/logout preserve the official terminal flow, status accepts only exact `Logged in using ChatGPT`/`Not logged in` stderr phrases, and mutations require the same status postcondition. Status may emit at most nine fixed, secret-free stage messages to Nagi's stderr so executable verification, the official Keychain lookup, and private-runtime cleanup are observable; the messages contain no paths, credentials, provider data, usernames, machine details, or timings. Logout delegates remote revoke semantics and never recursively deletes the managed home.
  The pinned native executable and digest are verified through POSIX source-parent checks (ordinary `0755` is valid) before copying to an ephemeral private runtime; only exact private paths are cleaned. Nagi never parses, copies, or prints credential material, accesses the normal Codex namespace, or automates a browser. Codex `0.151.0` may append `[projects."<canonical repository>"]` with exactly `trust_level = "trusted"` after an interactive confirmation; a bounded typed parser permits only those project records, rejects unknown keys/sections, duplicates, noncanonical or unsafe path syntax, non-trusted values, and oversized configs, and keeps project paths out of output/evidence. Authentication status and logout do not require historical repositories to remain present; `work start` may obtain the first selected-repository confirmation, while work reattachment/effect commands bind trust to the exact selected canonical repository and apply live owner/symlink checks. Default tests use a closed fake, the live contract is opt-in and status-only, and the production artifact remains one standalone executable. Detailed ACL, replacement-race, path-binding, and crash-residue boundaries are recorded in [ADR-0002](docs/adr/0002-managed-codex-authentication.md).

## GitHub Actions and credentials

- Pin every GitHub Action to an immutable commit SHA and keep `persist-credentials: false` on checkout steps.
- Keep workflow permissions at the least-privilege level.
- Use Securefix for automated workflow fixes and signed machine commits.
- Keep GPG keys, machine-user tokens, server app keys, and other strong credentials only in `civitaspo/securefix-server`.
- See [docs/securefix.md](docs/securefix.md) for the client/server setup.
